# Match performance fix — POCO, 02.10.2026

СДЕЛАНО

Обязательный порог основного сценария пройден в четырёх полных прогонах:
C1, 5 пар, Full, 120 Гц, по 60 совпадений и 3 ошибки. Последние два выполнены
после установки обычного debug APK, со звуком и вибрацией. На телефоне снова
стоит обычная сборка для пользовательской проверки. Цель raster 6–7 мс ещё
не достигнута; результат близок к порогу, отдельные медленные кадры остались.

Подтверждённые причины и изменения:

- Android SoundPool.play/stop выполнялись на главном потоке. Dart `unawaited`
  не устранял блокировку Android. В R6 звук выключен только для диагностики:
  задержка принятого callback → post-frame p95 уменьшилась со 126,743–141,722
  до 10,845 мс. Теперь SoundPool работает в отдельном последовательном потоке,
  очередь содержит один ожидающий звуковой запрос, приоритетный звук сохраняется,
  устаревшие запросы отбрасываются, pause/close отменяют старое поколение.
  Громкость, переключатели и WAV не изменены. В R7 длительность самой операции
  в worker: p95 98.572 мс, максимум 172.363 мс — она больше
  не задерживает Android UI. Это длительность вызова, не измерение акустической задержки.
- Ответ и таймер пересобирали большой экран, HUD и все карточки. Теперь локальные
  ValueNotifier обслуживают поле, прогресс, часы и комбо; журнал не запускает
  пересборку Match. У неизменившихся карточек сохраняются widgets/keys.
  Game/HUD: 155 → 2 сборки за основной прогон; маркеры обновляются по своему порогу.
  При idle пять тиков перестали пересобирать поле и 50 карточек.
- Пульс масштабировал текст и Material неявно анимировал рамку 200 мс поверх
  явной анимации. Успех/выбор сразу меняют поверхность, текст кэшируется отдельно,
  пульс и shake действуют на поверхность; `Material.animationDuration = 0`.
  R5 → R6: поверхность рисуется 2230 → 230 раз за прогон.
  Пульс correct и механика settle сохранены.
- Линия имеет локальный RepaintBoundary на каждый след. Геометрия рассчитывается
  при запуске, два слоя 6/2,4 dp без blur, готовые шаги draw и затем fade.
  После fade след и controller удаляются. Молния использует готовую геометрию,
  кэшированные надпись и shader, 3–5 частиц с фиксированными позициями;
  controller и overlay удаляются после завершения, старый callback не удаляет новый эффект.
- Ночной фон/звёзды были статическими ещё до этого блока: A «без ambient» был
  контрольным повтором. Фон и landscape объединены в одну непрозрачную
  кэшируемую поверхность за RepaintBoundary; при игре repaint отсутствует.
  Счётчик background=1 в полном окне относится к появлению экрана результата.
  Упрощены рамки/ореолы и смена карточек: без blur и без масштабирования всего
  batch; fade, связь, молния, correct feedback и направление Midnight Indigo сохранены.

Методика и воспроизведение:

POCO X4 Pro 5G (2201116PG), Android 13, 1080×2400, density 440, font scale 1.
`dumpsys display` подтвердил физические 120,00001 Гц перед/после каждого сценария.
Profile APK использует production TrainingGameScreen с C1-пулом 20 понятий,
5 пар, target=60, Random(26), три ошибки на 7/23/41, интервал между попытками
170 мс. Обе карточки пары вызываются быстро подряд; память и журнал свежие
в каждом сценарии. Callback вызывается только для доступной интерактивной карточки.
Это автоматический сценарий через реальные обработчики WordCard; ADB tap injection
не использовался. Реальные касания/ощущение реакции остаются для проверки человеком.
В R7/финале 60 попыток → 60 совпадений; исходно требовалось 70–74 попытки.

FrameTiming.buildDuration/rasterDuration, percentile ceil((n−1)q), без записи видео.
«>8,33/>16,67 мс» — количество кадров, где max(UI,raster) превышает бюджет;
это proxy превышения бюджета, не точный счётчик пропущенных дисплеем кадров.
Окно заканчивается через 850 мс после 60-го совпадения и содержит finish/result,
по одинаковому правилу до/после. Поиск карточки harness занимает p95 <0,9 мс
в финальных Full-прогонах и не входит в state-update stopwatch.

Profile command:
`flutter build apk --profile --no-pub --target tool/match_performance_probe.dart --dart-define=MATCH_PROFILE_CONTROLS=true`
Начальный A/B добавляет `--dart-define=MATCH_AB=true`;
финальная проверка добавляет `--dart-define=MATCH_PROFILE_HAPTICS=true`.
В обычном APK диагностические switches/counters выключены compile-time,
запускается обычный main.dart. Native-тест: существующий javac компилирует
BoundedAudioQueue.java и tool/BoundedAudioQueueTest.java, затем запускается
`java -cp <output> BoundedAudioQueueTest`.
